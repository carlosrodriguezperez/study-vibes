# Install and run (for AI agents)

Audience: an AI agent setting this up on a fresh machine so a human can run the demo. Follow the steps in order. Do not improvise commands; everything here is tested.

**Definition of success:** `npm run doctor` reports no blockers, and `http://localhost:3000/episode/demo-sets-0001` plays about 1:17 of audio without calling any provider.

---

## 1. Requirements

| Need | Notes |
|---|---|
| Node.js 20+ | 24.x tested |
| npm | comes with Node |
| `OPENROUTER_API_KEY` | for DeepSeek text generation |
| `GEMINI_API_KEY` | for Gemini text-to-speech |
| Network | `registry.npmjs.org`, `openrouter.ai`, `generativelanguage.googleapis.com` |

Python, Docker, and ffmpeg are **not** needed. There is one Node process.

---

## 2. Get the code

```bash
git clone https://github.com/carlosrodriguezperez/study-vibes.git
cd study-vibes
```

All commands below run inside the repository. The app lives in `web/`.

---

## 3. Install dependencies

```bash
cd web
npm install
```

Expected: exit code 0 and a `node_modules/` directory.

---

## 4. Add the secrets

From the repository root:

```bash
cp .env.example .env
```

Then fill both values in `.env`:

```
OPENROUTER_API_KEY=<your-openrouter-key>
GEMINI_API_KEY=<your-gemini-key>
```

Rules, non-negotiable:

- `.env` lives at the **repository root**, not in `web/`. `web/lib/env.ts` reads it at runtime.
- Never commit `.env`. It is gitignored; `.env.example` is the only tracked environment file.
- Never print the key values in logs or commits.

If you do not have the keys, stop and ask the human. The demo cannot be generated without them.

---

## 5. Check the install

```bash
npm run doctor
```

Expected output: Node, dependencies, `.env`, and both keys marked `ok`. A missing dev server and an unrendered demo are warnings at this stage, not failures.

Exit code 1 means a blocking problem. Fix it before continuing.

---

## 6. Start the app

```bash
npm run dev
```

Wait for `Ready`, then verify:

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000
```

Expected: `200`. Keep this process running in its own terminal.

---

## 7. Prepare the demo audio (required on a fresh machine)

Generated audio is gitignored, so a fresh clone has the script but no sound. With the server running:

```bash
npm run demo:prepare
```

Expected: `ready — N/N segments`, the duration, and `episode id: demo-sets-0001`.

Cost and limits:

- One TTS request per segment. The current demo is **one segment**, so one request.
- Gemini's free tier allows **10 requests per day per model**. A `429 RESOURCE_EXHAUSTED` means the quota is gone until it resets. Options: wait, set `TTS_MODEL` in `.env` to another TTS model, or enable billing on the Google project.
- Do **not** re-run this command "just in case". It spends quota. Run it only if the demo has no audio.

### Alternative: copy prepared audio

If another machine already ran `demo:prepare`, copy this folder to the same path here:

```
web/.data/episodes/demo-sets-0001/
```

It contains `episode.json` plus the WAV files. The app then works without any provider access.

---

## 8. Confirm it works

```bash
npm run doctor
```

Expected: `demo episode is ready (1/1 segments, 77s)` and the URL to open.

Open <http://localhost:3000/episode/demo-sets-0001> and press **Play**. If you hear audio, the install is complete.

Optional checks:

```bash
npm run lint     # must be clean
npm run build    # must succeed
npm run draft    # text-only script preview; spends no TTS quota
```

## 9. Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `OPENROUTER_API_KEY is missing` at runtime | `.env` is not at the repo root, or the server was started before the file existed. Fix the path, restart `npm run dev`. |
| Page renders unstyled | `postcss.config.mjs` missing. Reinstall with `npm install`. |
| Demo page has a transcript but no sound | Audio not rendered. Run `npm run demo:prepare` (see §7). |
| `429` from Gemini | Free-tier quota. See §7. |
| Audio still plays an older take | Hard reload (`Ctrl+Shift+R`). Audio URLs are versioned by script hash. |
| Port 3000 busy | `npm run dev -- -p 3001`, then set `BASE_URL=http://localhost:3001` for the scripts. |
| `web/AGENTS.md` appears in `git status` | Generated by Next.js; it is gitignored. Leave it alone. |
| Upload fails but the demo works | Provider outage. Use the pre-rendered demo; that is what it is for. |

---

## 10. Rules for the agent

- Keep `main` demoable.
- Never commit `.env`, `web/.data/`, `node_modules/`, or generated audio.
- Do not change `web/fixtures/demo-episode.json` without re-running `npm run demo:prepare`; the audio would no longer match the text.
- Prefer the pre-rendered demo for anything the human will watch. The live upload path is a bonus.
- If a command fails, report the exact error and stop. Do not invent flags or substitute providers.
